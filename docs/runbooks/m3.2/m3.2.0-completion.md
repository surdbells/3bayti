M3.2 / M3.3 / M3.4 phase ships under. Per locked decision Q-QI, this

**Goal:** Baseline Playwright coverage on all 4 existing public routes.

**Delivered:**

- 5 spec files covering 21 tests:
  - `home.spec.ts` — hero carousel + global app shell + JS errors + title/meta
  - `categories-index.spec.ts` — Shop by Category heading + grid
  - `category-detail.spec.ts` — dynamic slug from sitemap + JSON-LD

**Quality gate:** apps/web tsc 0 preserved. Angular build still produces 1933-URL sitemap.

### M3.2.0-B — Playwright setup for apps/mobile (`a475861`)

**Goal:** e2e coverage on Capacitor web preview. CI runs with `continue-on-error` initially per Q3=A.

**Delivered:**
- `apps/mobile/playwright.config.ts` — iPhone 14 Pro viewport with Chromium engine override (overrides device default WebKit per Q4=A)
- `apps/mobile/e2e/utils/preferences-mock.ts` — Capacitor Preferences plugin mock via `addInitScript`, with `mockAuthenticatedUser` / `mockAuthenticatedVendor` convenience helpers
- 4 spec files covering 12 tests:

  - `auth.spec.ts` — login + register page render
  - `catalog.spec.ts` — auth-gated catalog browse (skip-on-404 for evolving routes)
  - `my-orders.spec.ts` — auth + network-mocked my-orders page
- Authoring guide explaining web-preview limitations (no native plugin / gesture / OS-level a11y coverage)

**Quality gate:** apps/mobile tsc 6 baseline preserved.

### M3.2.0-C — Chromatic visual regression (`3b50248`)

**Goal:** Page-level visual diffs on every PR via archive-based capture.

**Tool selection:** Chromatic chosen over Percy per implementation plan §1.3 (native Storybook integration, free tier covers our 5,000 snapshots/month budget, TurboSnap optimization).

**Delivered:**
- `apps/web/e2e/utils/chromatic.ts` — wrapper around `@chromatic-com/playwright`'s `takeSnapshot`, with defensive try/catch (visual regression never breaks functional tests)
- 5 snapshot checkpoints added to existing spec files:
  - `home-page-default`
  - `categories-index`
  - `category-detail-<slug>`
  - `product-detail-default`
- `apps/web/chromatic.config.json` — onlyChanged (TurboSnap), externals (skip image-only changes), auto-accept main, skip dependabot
- `pnpm chromatic` script
- Runbook `docs/runbooks/m3.2/chromatic-runbook.md` — operator setup (one-time), PR comment reading guide, snapshot authoring, debugging false positives, baseline reset procedure, budget management

**Operator backlog (Q1=C):** Sign up at chromatic.com → add `CHROMATIC_PROJECT_TOKEN` to GitHub secrets → replace placeholder `projectId` in `chromatic.config.json` → remove `continue-on-error` from `web.yml`.

### M3.2.0-D — axe-core WCAG AA gate (`205016d`)

**Goal:** Automated accessibility gate on every primary load test. Allowlist mechanism prevents M3.2.0 closure on remediation sprint (Q2=B).

**Delivered:**
- `apps/web/e2e/utils/a11y.ts` — `expectNoA11yViolations(page, info, options?)` helper. Enforces wcag2a + wcag2aa + wcag21a + wcag21aa tags. Attaches violation JSON on failure. Per-test exclusion via `excludeRules + excludeSelectors + reason` annotation
- `apps/web/e2e/utils/a11y-allowlist.ts` — structural `AxeResult` type, 4-field entries (rule/urlPattern/reason/remediationPhase/expiresAt), expiry-aware filter
- 4 spec files wired with a11y check at primary load test
- `apps/mobile/e2e/utils/a11y.ts` — parallel helper (no allowlist yet; mobile pages predate this gate)
- Runbook `docs/runbooks/m3.2/a11y-guide.md` — WCAG AA scope, top-10 violation patterns with fix examples, allowlist usage, debugging procedure
- Runbook `docs/runbooks/m3.2/a11y-baseline.md` — empty-allowlist start position, capture procedure for first CI run, expiry policy, counts ledger

**Operator backlog:** First CI run captures actual baseline violations. Operator reviews each, decides fix-now vs allowlist, lands updates as M3.2.0-D supplementary commit.

### M3.2.0-E — Storybook scaffold (`0b43f6e`)

**Goal:** Component library development sandbox in `packages/shared-ui`.

**Framework selection:** `@storybook/html-vite` chosen over `@storybook/angular`. Rationale: shared-ui is intentionally framework-agnostic per its README; depending on Angular would lock all consuming apps to the same Angular version.

**Delivered:**
- `packages/shared-ui/.storybook/main.ts` — html-vite framework, story discovery, addon-essentials + addon-a11y, telemetry disabled
- `packages/shared-ui/.storybook/preview.ts` — 3 viewports (matching responsive.spec.ts), 3 backgrounds, a11y panel with WCAG AA tag set
- `packages/shared-ui/src/components/Welcome.stories.ts` — bootstrap placeholder validating the toolchain
- `packages/shared-ui/STORYBOOK.md` — authoring guide (framework rationale, story conventions, decorator pattern, a11y addon usage, RTL toggle example, step-by-step new-component walkthrough)
- `packages/shared-ui/.gitignore` — storybook-static/, .cache
- `storybook` + `build-storybook` scripts

**Drive-by fix:** `apps/web/package.json` and `apps/mobile/package.json` had missing `@axe-core/playwright` entries from M3.2.0-D (pnpm-lock.yaml was updated but package.json files weren't). Reconciled in this commit.
