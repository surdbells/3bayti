## Executive summary

M3.2.X.15 ships **display-only multi-currency** support. International visitors browsing the catalog can pass `?currency=USD` (or EUR, SAR, GBP) and see prices in their preferred currency alongside the canonical AED amount. Settlement remains 100% AED across all Cart, Order, payment, payout, and refund entities — Q-Scope = A locked.

What this phase delivered:

- New single-table additive migration: `fx_rates` (id, base_code, target_code, rate, updated_at, updated_by_user_id) with UNIQUE constraint + target_code index. Seeded with 5 rows (AED→AED identity + AED→{USD, EUR, SAR, GBP}).
- New `Currency` PHP backed enum with case-insensitive `fromQueryParamOrAed()` parser and graceful fallback to AED on unknown input.
- New `FxRate` Doctrine entity with constructor + setRate validation: regex check, positive-rate guard (defeats bcmath's silent zero-coercion), and `<1000` guard (defeats base/target inversion typos).
- New `CurrencyConversionService` — pure read-only service with bcmath multiplication, manual HALF_UP rounding via bias-add-then-truncate, AED identity short-circuit, missing-rate fallback, and PSR-3 staleness observability (`fx_rate.stale` warning at >48 hours; `fx_rate.missing` warning when no rate exists).
- New `CurrencyContextMiddleware` parsing `?currency=` query parameter into a request attribute. Wired globally; pure middleware so non-catalog routes ignore it.
- `ProductSerializer` integration via optional constructor parameter + fluent `withDisplayCurrency()` and `configureFromRequest()` methods. Six catalog controllers updated with one-line chained configuration. ListStylesController NOT modified (StyleSerializer emits raw decimal strings; out of v1 scope).
- Two new admin endpoints: `GET /v3/admin/fx-rates` (list with per-row staleness flags + meta block) and `PUT /v3/admin/fx-rates/{target}` (upsert with AED-target rejection + AuditEmitter integration).
- New `snapshotFxRate` strategy in AuditEmitter for the audit_log trail.

Before this phase:

- Every product price was hardcoded as `{amount, currency: 'AED'}` in ProductSerializer. International visitors had to mentally convert AED prices to their own currency, adding friction to evaluation. Tourist customers in particular were a known drop-off vector.
- No FX rates infrastructure existed anywhere in the codebase.
- No request-scoped value other than the auth user could be passed from middleware to serializers.

After this phase:

- Visitors pass `?currency=GBP` and see prices like `{amount: 78.29, currency: 'GBP', source_amount: 365.00, source_currency: 'AED'}` — both the converted display value AND the canonical AED amount in a single response. Clients can render 'GBP 78.29 (AED 365)' without a second roundtrip.
- Operator manages rates via a simple PUT-per-currency admin endpoint, audited via existing audit_log infrastructure.
- Stale rates (>48h) emit PSR-3 warnings so ops sees them in dashboards. Missing rates degrade gracefully to AED single-amount shape (no enumeration leak, no 422).
- All cart/order/checkout flows return AED regardless of `?currency=` — the customer is shown what they'll actually be charged at settlement time. The X.15 layer is strictly catalog-only.

## Architectural patterns reinforced

This phase exercised the following patterns:

1. **Single-table additive migration with seed values** — standard X-series pattern.
2. **FK ON DELETE SET NULL preserving audit trail** (`fx_rates.updated_by_user_id`) — locked from M3.1.x.
3. **UNIQUE constraint on natural key + index on filter column** — same shape as `notification_logs.template`.
4. **Backed PHP enum with case-insensitive parser + graceful fallback** — Currency::fromQueryParamOrAed mirrors EmailTemplate::tryFrom semantics.
5. **Decimal-string-not-float arithmetic for money** — locked from M2 Order serialization; X.15-C extends with bcmath multiplication + manual HALF_UP rounding.
6. **HALF_UP via bias-add-then-truncate bcmath trick** (NEW, locked X.15-C) — `bcadd(value, halfBias, scale8)` then `bcadd(., 0, decimals)` to truncate. Reusable for any money-conversion service.
7. **Identity short-circuit in pure services** (CurrencyConversionService AED→AED) — pure functions with hot-path optimization should test the trivial case before the general one.
8. **In-memory cache scoped to service instance** — relies on per-request DI container scope (locked from M1.x).
9. **PSR-3 timing/state observability** (`fx_rate.stale`, `fx_rate.missing`) for ops dashboards — same shape as `cart_abandonment_finder.computed` etc.
10. **PSR-15 middleware writing request attributes downstream code consumes** — locked from M1.4 AuthMiddleware (ATTR_USER + ATTR_CLAIMS).
11. **Fluent self-returning serializer configuration** (NEW informal pattern, locked X.15-E) — `$serializer->configureFromRequest($req)->shapeMethod()`. Reusable for future per-request serializer config (locale, audience scope, etc.).
12. **Backward-compatible optional constructor parameters for additive features** — `ProductSerializer(?CurrencyConversionService $conversion = null)` keeps every existing call site working without changes.
13. **Defensive type-checking on PSR-7 attributes** — the attribute contract is by name only; serializers reading attributes must validate the value's type before use.
14. **Path placeholder regex constraints for early rejection of obviously-bad input** — `{target:[A-Za-z]{3}}` rejects garbage before the controller even runs.
15. **Defensive validation guards** (AED-as-target rejection in upsert) that protect invariants downstream services rely on (the identity short-circuit assumes AED→AED rate is always 1.0).
16. **AuditEmitter snapshot strategy added per entity type** — same pattern as Brand, Vendor, Category, PromoCode; the X.15-F change adds FxRate as the eighth strategy.
17. **Admin mutator with audit integration** (X.14-D pattern) — snapshot before → mutate → flush → recordUpdate with before/after diff.
18. **Real-service-with-fake-deps integration test for observability** (X.14-E / X.17-E / X.11-H / X.15-G — FOURTH occurrence; firmly locked).

## Security considerations

1. **No SQL injection surface** — all DBAL queries use parameter binding. `Currency::fromQueryParamOrAed` validates the input is a known enum case before the rate is looked up by enum value.
2. **No PII in audit_log** — FxRate snapshots contain base/target codes + rate + timestamp + actor id. No customer or vendor information.
3. **Admin endpoint protected by AdminAuthMiddleware** — both GET and PUT require admin role.
4. **AED-as-target rejection** prevents an operator typo from corrupting the identity short-circuit and breaking every conversion downstream.
5. **Rate < 1000 guard** in `FxRate::setRate` catches base/target inversion typos (e.g. typing 367.0 instead of 0.272 for AED→USD) before the row is persisted.
6. **Rate > 0 guard** catches zero rates that would zero out customer-displayed prices (bcmath silently coerces bad numeric strings to 0).
7. **3-letter regex on path placeholder** rejects garbage URLs like `/v3/admin/fx-rates/foo` before the controller runs.
8. **Identity short-circuit cannot be bypassed** — even if an operator somehow persists a non-1 rate for AED→AED, `convert(..., Currency::AED)` returns early without consulting the rate table.

## What's NOT in X.15 (deferred or scoped out)

- **Cart/checkout/order/refund display in non-AED currencies** — Q-Scope = A locked: catalog only. Settlement-adjacent surfaces display AED to avoid customer confusion ("I see £75 but my card was charged AED 365").
- **Auto-detect currency from IP geolocation** — Q-RequestContext = A locked: explicit query param only. GeoIP databases + VPN/proxy edge cases would complicate v1 without clear UX win. The client UI picks a default from device locale and persists in localStorage.
- **Accept-Language fallback** — same Q-RequestContext lock; browser language ≠ shopping currency preference.
- **Per-currency rounding policy** — Q-Rounding = A locked at 2 decimals HALF_UP. JPY (0 decimals) and BHD/KWD/OMR (3 decimals) would require per-currency policy in the conversion service; deferred to operator follow-up #28 when those currencies get added.
- **Currency chain conversion (USD→AED→GBP)** — Q-RateShape = A locked at AED base. v1 only supports AED→{target} direct conversions. If a future requirement needs USD-based pricing for certain regions, the conversion service would need a "best path" algorithm.
- **Promotional/discount display in non-AED** — promo codes today carry an AED-denominated `discount_value`. Multi-currency display of the discount preview is an enhancement; v1 leaves promotional UI in AED.
- **Tax / VAT calculation in non-AED** — UAE VAT is computed on AED amounts at checkout; v1 doesn't display VAT in non-AED currencies on the catalog. Cart/checkout show AED VAT.
- **Currency switcher with conversion history** — a "see how much this product costs over time in USD" feature. Out of scope; the audit_log captures rate changes for ops but not for customer-facing history.
- **Reverse conversion (entry in USD → AED)** — admins enter rates as AED→{target}. There's no "enter the rate as target→AED and let me compute" affordance. ~0.5 day if requested.
- **Cron-driven staleness alerting** — operator follow-up #31 covers wiring the existing `fx_rate.stale` PSR-3 warning into the alerting infrastructure when it crosses a threshold.
- **Paid auto-refresh** — operator follow-up #27; manual entry is sufficient for v1.
