## Executive summary

M3.2.X.2 ships `/v3/featured-vendors`, replacing the broken legacy
`/v2/featured-vendors` endpoint that apps/web Designer Spotlight
depends on. The new endpoint provides admin-managed vendor curation
with embedded top-N product thumbnails per vendor + a SQL-aggregated
rating.

Before this phase:
- `apps/web` home-page Designer Spotlight section returned empty
  (silently — `catchError` in `home-data.service.ts` hides failed strips)
- Legacy `/v2/featured-vendors` returned 500 in production
- No `is_featured` column on the Vendor entity

After this phase:
- `GET /v3/featured-vendors` returns a curated list of active +
  featured vendors with embedded products and rating
- `PUT /v3/admin/vendors/{id}` accepts `is_featured: true|false` for
  admin-managed curation
- Apps/web feature flag flipped `target='old'` → `'new'`
- Apps/web Designer Spotlight strip resolves to the new endpoint

Operator must seed 3-4 vendors as `is_featured: true` on production
before the Spotlight strip will render anything meaningful.

## Wire contract reference

The endpoint returns the exact shape consumed by apps/web's
`FeaturedVendor[]` interface (defined in
`apps/web/src/app/features/catalog/designer-card.ts`):

```json
{
  "data": [
    {
      "slug": "almas-fashion",
      "name": "Almas Fashion",
      "description": "A luxe label.",
      "rating": 4.6,
      "rating_count": 87,
      "products": [
        {
          "id": 123,
          "slug": "silk-abaya",
          "image_url": "https://cdn.example/silk.jpg",
          "name": "Silk Abaya"
        }
      ]
    }
  ],
  "meta": {
    "total": 4,
    "limit": 4,
    "offset": 0,
    "has_more": false
  }
}
```

Edge cases:
- Vendor with zero approved reviews → `rating: null, rating_count: 0`
- Vendor with no active products → `products: []` (vendor still appears; respect admin curation)
- Empty featured set → top-level `data: []`, 200 OK (not 404)
- `?limit=999` → clamped silently to 12
- `?limit=-5` or `?limit=abc` → falls back to default 4
