## Executive summary

M3.2.Y.1 delivered the entire customer-facing authentication surface for the new Angular SSR web app:

- **Five pages**: `/login`, `/register`, `/verify-phone`, `/forgot-password`, `/reset-password`. Each Reactive Forms with full validation, error mapping, and i18n.
- **Auth core**: AuthService + AccessTokenStore + refresh interceptor (single-flight) + functional CanMatch+CanActivate guards + APP_INITIALIZER hydration.
- **Cookie-bound BFF**: Angular SSR auth-proxy at `/auth-proxy/*` issuing HttpOnly Secure SameSite=Lax refresh cookies scoped to `Path=/auth-proxy`. Access tokens stay in memory only.
- **Shared form primitives**: FormField, PhoneInput (E.164 with 30-country list including GCC + 24 tourist origins), PasswordStrength (lazy zxcvbn-ts), Toast, mapApiErrors.
- **Auth-aware header**: UserMenuComponent dropdown for authenticated users; FEATURE_AUTH_HEADER_CTA-gated Sign in / Register CTAs for anonymous (default false until Y.2).
- **i18n**: 79 English keys, 36+ Arabic translations with real Arabic text, RTL via `<html dir>` + logical CSS properties. Locale switcher in header. Locale changes by authenticated users persist to API via PATCH `/v3/me/profile`.

**Quality:** 284 unit tests across 22 files (started from 21 pre-Y.1). All five web/backend gates green at every commit. Six production-class defects caught and fixed by tests during the build (open-redirect, NG0200 cycle, prerender hang, NG0303 password-strength NgIf, etc.). Zero regressions.

## Architectural patterns established (referenced by Y.2+)

1. **Angular SSR BFF auth-proxy** — refresh token HttpOnly cookie at edge; access token memory-only. Pattern lives in `apps/web/src/server/auth-proxy/`. Y.2 cart/checkout will go direct via Bearer for non-cookie endpoints; only the auth flow needs the proxy.

2. **Single-flight refresh interceptor** — `refresh.interceptor.ts`. Concurrent 401s queue against one in-flight promise. Pattern reusable for any 401-retry interceptor.

3. **Functional guards (CanMatch + CanActivate)** — chunk-level deferral via CanMatch + runtime check via CanActivate. `guestActivateGuard` / `authActivateGuard` in `auth.guards.ts`. Y.4+ account pages use authActivateGuard.

4. **Memory-only access token with TransferState bridge** — SSR-rendered HTML doesn't embed the token; client hydration receives it via the BFF /me roundtrip.

5. **Lazy AuthService via injector.get** — breaks the APP_INITIALIZER NG0200 cycle when the interceptor needs auth. Pattern: `injector.get(AuthService)` inside the interceptor body, NOT in the constructor.

6. **REQUEST-null prerender bail** — `hydrate()` short-circuits when SSR has no inbound request (i.e. build-time prerender). The auth-proxy is unreachable from the build machine; bailing on REQUEST===null avoids the prerender hang.

7. **Stable error key via `data-error-key` attribute** — FormFieldComponent exposes the resolved i18n key as a DOM attribute so tests can assert on it without depending on HTTP-loaded translations.

8. **Open-redirect defense** (`isSafeInAppPath`) — single leading `/`, NOT `//host`. Both guard and login page apply it; tests prove both reject `//evil.example` and `https://evil.example`.

9. **Anti-enumeration in /forgot-password** — frontend NEVER branches on `fake-` prefix; OTP_INVALID_CODE indistinguishable on both real and fake paths.

10. **Shared form primitives composition** — every page composes FormField + (Phone | Password | code-input) + Toast + mapApiErrors. New auth-adjacent pages (Y.4 profile edit, etc.) reuse this stack.

11. **sessionStorage refresh-safety for OTP flow** — /verify-phone persists `verification_id` + masked `phone` per-tab so a hard refresh doesn't strip the URL query string.

12. **30s resend cooldown** — setInterval + signal countdown with ngOnDestroy cleanup. Used by verify-phone; reusable for any "resend" pattern in Y.2+.

13. **Locale push via effect() side-channel** — `effect()` watching LocaleService.current() in AuthService; decouples i18n from auth state. lastPushedLocale dedup field avoids redundant chatter.

## Deferred work (Y.2-prep staging-smoke pass)

The Y.1 implementation plan called for per-page Playwright + Chromatic + axe; these were deliberately deferred to a single staging-smoke pass before Y.2 ships, for two reasons:

1. **Sandbox limitations**: Playwright requires browser binary downloads (~150 MB, 5+ minutes) AND a running wrangler dev session with the BFF actually reachable. Neither is sustainable in the agent's tool budget for per-page runs.

2. **Single-pass economics**: A staging-smoke pass exercises all five pages together against the live API — closer to what real users experience than each page mocked in isolation. The unit-test layer (284 tests at close) covers component logic deterministically; Playwright covers the integration story once.

**Deferred items, to be picked up before any Y.2 user-facing UI:**

- [ ] **Playwright e2e for /login** — happy path, invalid-credentials, network-error, returnUrl honouring, open-redirect rejection
- [ ] **Playwright e2e for /register** — happy path, CONFLICT_EMAIL_TAKEN inline, CONFLICT_PHONE_TAKEN inline, country-code derivation
- [ ] **Playwright e2e for /verify-phone** — happy path, OTP_INVALID_CODE, sessionStorage refresh-safety, resend cooldown countdown
- [ ] **Playwright e2e for /forgot-password + /reset-password** — happy path on real email, happy path on fake- vid (anti-enumeration parity), password mismatch validator, OTP_INVALID_CODE
- [ ] **Header e2e** — anonymous (CTA hidden), anonymous (CTA shown via DI override), authenticated user-menu (open/close/sign-out), locale switcher EN ⇄ AR
- [ ] **Storybook stories for Y.1-D primitives** — FormField, PhoneInput (30 countries), PasswordStrength (lazy load demo), Toast (4 kinds, dismiss interaction). Storybook isn't yet installed in apps/web; setup is its own sub-phase.
- [ ] **Chromatic baselines** — once stories exist, baseline all auth-card variants in both LTR and RTL
- [ ] **axe a11y baselines** — Playwright + @axe-core/playwright integration; WCAG AA on all five pages plus the user-menu open state

## Y.2 entry point (cart + checkout + orders, ~6-8 weeks)

The next sub-phase begins from this commit. Things Y.2 inherits:

- **Auth state available everywhere**: `inject(AuthService).currentUser()` returns the live user signal anywhere in the app. `isAuthenticated()` is the gate for cart-merge logic, checkout step gating, etc.
- **Refresh interceptor on every HttpClient call**: any Bearer-bound API call automatically retries on 401 with a refreshed token. Y.2 cart/order endpoints don't need to think about this.
- **Toast service for non-form errors**: ToastService.error('cart.errors.outOfStock') for status messages.
- **mapApiErrors helper for form pages**: same pattern as Y.1's 5 pages, just with cart/checkout-specific error codes.
- **i18n keys ready**: namespace pattern is `<feature>.<surface>.<key>`; the Y.2 work will add `cart.*`, `checkout.*`, `orders.*` keys following the same shape.
- **FEATURE_AUTH_HEADER_CTA flag**: Y.2 first work item is to flip this to `true` once /cart-promoted-checkout makes signing in genuinely useful (e.g. "save your cart" prompts).
