## What shipped

### New infrastructure

**Two new injectable services** in `apps/mobile/src/app/core/services/`:

- `CheckoutStatusPollService` — Polls `GET /v3/checkout/status/{ref}` at 2s intervals for up to 60s (industry-standard Stripe/PayPal/Adyen defaults) after webview close. Emits exactly one `PollOutcome`: `paid` | `failed` | `timeout` | `error`. Subscribing starts the poll; unsubscribing cancels (no zombie polls after navigation).

- `LocalCartService` + `CartMergeService` — Guest cart storage in IndexedDB (DB `3bayti_local_cart` v1, single `items` object store, autoIncrement `localId` keyPath); variant-aware merge matching server `Cart::findEquivalentItem`; quantity cap 999. CartMergeService orchestrates `list → POST /v3/cart/merge → clear`. Never throws (errors captured in `MergeResult`). Preserves local cart on failure for retry.

### Adapter extensions

- New `MUTATION_REQUEST_TRANSFORMS` registry — body reshape + path-param extraction for POST/PATCH/DELETE endpoints. Five cart transforms + one checkout transform.
- New `AUTHED_GET_REQUEST_TRANSFORMS` registry — POST→GET conversion for authenticated reads. One order-list transform.
- New `MUTATION_RESPONSE_TRANSFORMS` registry — v3 envelope → mobile binding shape. Nine transforms covering all M3.1.6 v3 endpoints.
- `callV3()` consults the request registry on Path 1 (exact-method match) when `target='new'`.
- `tryConvertPostToGet()` extended to consult both anonymous (catalog) and authenticated (order) registries; attaches Bearer header in the authed path.
- `envelopeAndTransform()` consults both response registries (catalog + mutation).

### Page-level changes (dual-shape support)

Every consuming page now detects and handles BOTH legacy and v3 response shapes, so per-endpoint rollback works without further code changes:

- **`cart.page.ts`** — `load_cart()` branches on `Array.isArray(data)` (legacy) vs `data.items` array (v3). Guest mode (`isGuest=true`) reads/writes through `LocalCartService` instead of NetworkService.
- **`checkout.page.ts`** — Same dual-shape pattern in `load_cart()`. `checkout_initiate()` detects v3 (`response.data.url`) vs legacy (`response.result.checkoutData.postUrl`) response shapes. Webview redirect listener matches BOTH `customer/complete?...` (legacy) AND `/v3/checkout/return/{ref}` (v3) return URL prefixes.
- **`product.page.ts`** — Guest mode allows browsing + adding to cart without redirect to login. `addToCart()` branches: guest writes `LocalCartItem` to IndexedDB; authenticated path unchanged.
- **`my-orders.page.ts`** — `extractOrders()` helper handles both legacy array shape and v3 `{orders, pagination}` shape.
- **`process.page.ts`** — `finalize()` branches on presence of `orderReference` query param: v3 path polls via `CheckoutStatusPollService`; legacy path uses existing `finalizePayment` POST.
- **`login.page.ts`** — Injects `CartMergeService`. After token storage, calls `mergeIfAny(authBody)` in background (non-blocking — login completion isn't gated on merge success). Surfaces skipped-items toast if any.

## Customer happy path (post-flip)

```
1. Guest browses products
2. Guest taps add-to-cart on product page
3. LocalCartService stores in IndexedDB
4. Guest opens cart — sees device-local cart from IDB
5. Guest signs in (or signs up)
6. login.page.ts: Preferences.set(user); fire-and-forget cartMerge.mergeIfAny()
7. CartMergeService: POST /v3/cart/merge with items[]; on success, IDB cleared
8. User opens cart — sees server-side cart (post-merge)
9. User taps Checkout
10. checkout.page POSTs /v3/checkout/initiate
11. v3 server: derives totals from cart, generates order_reference, creates pending Order, calls Noon INITIATE
12. v3 returns { url, order_reference, order_id }
13. checkout.page opens InAppBrowser webview with `url`
14. User completes payment in Noon hosted checkout
15. Noon redirects webview to https://api.3bayti.ae/v3/checkout/return/{ref}
16. urlChangeEvent listener extracts order_reference from path, closes webview
17. checkout.page navigates to /process?orderReference={ref}
18. process.page.finalize() invokes CheckoutStatusPollService.pollUntilTerminal(ref)
19. Poll runs every 2s, max 60s
20. Meanwhile: Noon hits POST /v3/payment/webhook/noon (server-to-server)
21. NoonWebhookController retrieves order from Noon (gateway.retrieveOrder)
22. v3 marks Order.paid (idempotent)
23. Mobile's next poll tick sees terminal=true, paid=true
24. process.page navigates to /success (replaceUrl)
```

Every step is tested. Webhook safety (M3.1.6f2) ensures even spoofed webhooks can't mark an order paid because `gateway.retrieveOrder` is the authoritative source-of-record.

## Failure paths (verified)

- **Network failure during initiate**: `error_notification` shown, user stays on checkout page
- **Network failure during webhook**: Noon retries; reconciliation cron (M3.1.7) catches stuck orders
- **Webhook signature failure**: `LoggingOnlyVerifier` logs (M3.1.7 binds real HMAC verifier)
- **Poll timeout** (60s without webhook): `toast.info` shown, user navigated to `/my-orders` where they can refresh
- **Poll error** (unexpected): user navigated to `/failed`
- **Cart merge network failure**: local cart preserved; user can retry by signing out and signing back in
- **Cart merge skipped items**: surfaced via `text_cart_merge_skipped_some` toast
- **Per-endpoint regression**: revert single `target: 'new'` to `'old'` in feature-flags.ts; dual-shape page bindings keep working
