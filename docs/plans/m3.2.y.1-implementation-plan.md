## 0. Locked decisions (12 Q-decisions)

Locked at the planning kickoff turn (May 19, 2026). Any change requires an explicit revision.

| # | Decision | Locked value | Rationale |
|---|---|---|---|
| Q-TokenStorage | Where do JWT tokens live in the browser? | **A — HttpOnly cookie (refresh) + in-memory access token** | Strongest XSS resistance. No API change needed: Angular SSR `server.ts` acts as a BFF that swaps cookies on login/refresh, strips refresh tokens from JSON bodies before forwarding to browser. |
| Q-RefreshStrategy | How does the access token refresh? | **C — Pre-emptive + reactive 401 retry** | Pre-emptive (~60s before expiry) avoids user-visible blips; reactive covers sleep/wake/clock-skew edge cases. Single-flight queueing prevents concurrent refresh storms. |
| Q-RouteGuards | Which guard pattern? | **C — CanMatch + CanActivate combo** | CanMatch defers the lazy chunk load for anon users; CanActivate does the runtime re-auth check. Applied to `/account/*` + `/checkout/*` in this stream. |
| Q-ResetFlow | How does password reset work end-to-end? | **B — OTP-based reset (existing API shape)** | API already implements `POST /v3/auth/reset` → `{verification_id}`; `POST /v3/auth/reset/confirm` → auto-login token pair. No API change. |
| Q-OTP | When is OTP required? | **Phone OTP at registration + at password reset; password-only login** | Confirmed by RegisterController + ResetController contract inspection. No per-login OTP. |
| Q-RegisterFields | What's on the registration form? | **D — Match RegisterInput contract exactly: email + E.164 phone + password (≥8) + country_code (default 'AE') + optional first_name + optional last_name** | Mirrors `apps/api/src/Http/Controllers/Auth/Dto/RegisterInput.php` validation rules verbatim. |
| Q-Locale | How does the web app handle EN/AR? | **A — Browser-language detection + header switcher; persist to `bayti_locale` cookie; full Arabic translations in Y.1** | SSR-aware: `Accept-Language` header server-side, `navigator.language` client-side fallback. RTL CSS via Tailwind `rtl:` variants. Authenticated users sync to `User.locale` (X.7 surface). |
| Q-FormLibrary | Reactive vs Template-driven vs Signal Forms | **A — Reactive Forms with typed `FormControl<T>`** | Battle-tested, type-safe, plays well with Playwright. Angular 21's signal forms are still experimental. |
| Q-Validation | Client-side validation depth | **C — Mirror API rules + zxcvbn password strength meter** | Reduces server roundtrips; password meter is master-plan-mandated for Y.1-C. zxcvbn lazy-loaded to keep auth-less catalog bundle clean. |
| Q-ErrorPresentation | How do API errors render? | **A — Per-field inline + global toast for unmapped** | `mapApiErrors(ApiError, FormGroup)` helper translates API error codes to typed FormControl errors. |
| Q-Tests | Test coverage shape per page | **B — vitest unit tests for AuthService/guards/interceptor/LocaleService + Playwright e2e per page** | AuthService logic (especially single-flight refresh queueing) needs unit coverage; pages covered by e2e. |
| Q-FeatureFlag | Is Y.1 flag-gated? | **C — Routes always live; header user-menu CTA flag-gated** behind `FEATURE_AUTH_HEADER_CTA` | apps/web is staging-only per Q-Web-Launch; we don't need flag-gating for routes themselves, but the header CTA stays hidden until Y.2 ships cart/checkout to avoid dead-end UX. |

## 1. API contract reference (verified May 19, 2026)

All endpoints under `/v3/auth/*` consumed by Y.1. Reference snapshot for sub-phase implementations.

| Endpoint | Request body | Success response | Notes |
|---|---|---|---|
| `POST /v3/auth/register` | `{email, phone (E.164), password (≥8), country_code? = 'AE', first_name?, last_name?}` | 201 `{verification_id, user: {email, phone, country_code, is_phone_verified: false}}` | No tokens yet; user in unverified state. |
| `POST /v3/auth/confirm` | `{verification_id, code (6 digits)}` | 200 `{access_token, access_token_expires_at, refresh_token, refresh_token_expires_at, user}` | Auto-login on confirm. |
| `POST /v3/auth/send-otp` | `{email}` | 200 `{verification_id}` | Re-send registration OTP only (not reset OTP). |
| `POST /v3/auth/login` | `{email, password}` | 200 `{access_token, access_token_expires_at, refresh_token, refresh_token_expires_at, user}` | Phone-unverified users can log in; UI routes to `/verify-phone` via `user.is_phone_verified=false`. |
| `POST /v3/auth/refresh` | `{refresh_token}` | 200 (same shape as `/login`) | **Single-use rotation** — every refresh emits a new refresh token. |
| `POST /v3/auth/reset` | `{email}` | 200 `{verification_id}` | Always 200 (anti-enumeration). `fake-` prefix vid for non-existent/deactivated accounts. |
| `POST /v3/auth/reset/confirm` | `{verification_id, code, new_password}` | 200 `{access_token, refresh_token, *_expires_at, user}` | Auto-login on reset. |
| `POST /v3/auth/logout` | `{refresh_token}` | 204 | Invalidates the presented refresh token row. |
| `POST /v3/auth/logout-all` | (auth'd, no body) | 204 | Invalidates all refresh tokens for the user. |
| `GET /v3/auth/me` | (auth'd, no body) | 200 user payload | For initial session hydration. |

**Token TTLs:** access = 900s (15 min), refresh = 604800s (7 days).

**Error codes consumed by UI:**
- `AUTH_INVALID_CREDENTIALS` (401) → login page inline error
- `AUTH_ACCOUNT_INACTIVE` (401) → login page banner
- `CONFLICT_EMAIL_TAKEN` (409) → register form email-field error
- `CONFLICT_PHONE_TAKEN` (409) → register form phone-field error
- `OTP_RATE_LIMITED` (429) → toast + cooldown timer
- `OTP_PROVIDER_ERROR` (502) → toast + retry CTA
- `VALIDATION_FAILED` (422) → per-field error mapping

## 2. Scope

### In scope (Y.1)

- `LocaleService` + ngx-translate scaffolding + RTL + EN/AR translations for every Y.1 page
- Header locale switcher
- `AuthService` (Angular signals) — access-token memory, user state, login/register/refresh/logout, pre-emptive auto-refresh scheduler
- Angular SSR BFF auth proxy in `server.ts` (8 routes under `/auth-proxy/*`)
- `refreshInterceptor` — reactive 401 retry with single-flight queueing
- `authMatchGuard` + `authActivateGuard` (functional) for `/account/*` + `/checkout/*` patterns
- Shared form primitives: `<bayti-form-field>`, `<bayti-password-strength>` (zxcvbn lazy-loaded), `<bayti-phone-input>`, toast service, `mapApiErrors` helper
- 5 pages: `/login`, `/register`, `/verify-phone`, `/forgot-password`, `/reset-password`
- Auth-aware header (CTAs flag-gated behind `FEATURE_AUTH_HEADER_CTA`)
- vitest unit tests for AuthService, refresh interceptor, route guards, LocaleService, BFF proxy
- Playwright e2e + Chromatic + axe per page

### Out of scope (Y.1)

- Cart / checkout / order pages (Y.2)
- Account profile/addresses pages (Y.4–Y.5)
- Phone-change / email-change flows (M5)
- 2FA at login (M5)
- Account lockout on failed attempts (M5)
- Social login (deferred indefinitely)
- "Remember me" toggle
- Any API changes (entire Y.1 is consumer-side)

## 7. Key risks + mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| ngx-translate SSR transfer state edge cases | Medium | `TranslateHttpLoader` + TransferState integration; covered by Playwright SSR-render checks. |
| Cloudflare Workers `Set-Cookie` quirks | Low | Test against `wrangler dev` in Y.1-C; Wrangler already in deps. |
| AR translation quality without native review | Low | Reuse X.7's MSA register (formal, business tone); flag for operator review pre-prod (not a hard blocker). |
| Pre-emptive refresh timer surviving navigations and SSR | Medium | Root-injected scheduler with `inject(ApplicationRef).isStable` integration; unit-tested. |
| zxcvbn bundle size (~400KB pre-min) | Low | Lazy-loaded only on register + reset routes; never on the auth-less catalog. |
| Phone country picker library bloat | Medium | Hand-built `<bayti-phone-input>` with curated GCC+tourist list (~25 entries); full intl deferred to Y.4. |
| Single-flight refresh queueing bugs (concurrent 401s) | Medium | Full vitest coverage with simulated concurrent calls; explicit "first request wins, subsequent share inflight promise" assertions. |
| SSR vs client locale mismatch (hydration warning) | Low | LocaleService chooses locale server-side via Accept-Language; client reads same cookie at hydration; no detection diff. |

## 8. Locked architectural patterns reinforced

- **Real-service-with-fake-deps integration test** (X.14-E / X.17-E / X.11-H / X.15-G / X.13-F / X.12-H lineage) — BFF proxy tests use real Express + fake API responses.

- **Opaque-on-failure verify** (X.11-E lineage) — frontend never reveals "wrong code" vs "expired vid" vs "user not found"; matches anti-enumeration posture from ResetController.

## 9. New architectural patterns introduced

- **Angular SSR BFF auth proxy** — refresh token stays HttpOnly cookie at edge; access token in-memory only; SSR is the only refresh-caller. Reusable for any sensitive cookie pattern in Stream Y.
- **Single-flight refresh interceptor** — concurrent 401s queue against one inflight refresh promise; pattern for any token-refresh interceptor.
- **Functional CanMatch + CanActivate combo guard** — chunk-level deferral + runtime check; reusable for `/account/*`, `/checkout/*`, vendor surfaces later.
- **Memory-only access token store with TransferState bridge** — SSR-aware token handoff without `localStorage` exposure.
