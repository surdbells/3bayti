## 1. What Y.3 delivered

The full round-trip that turns a Noon hosted-checkout result into a confirmed (or failed) order in the storefront:

```
/checkout/payment  (Y.2-F)
   │  window.location.assign(checkout_url)
   ▼
Noon hosted checkout  (shopper pays / cancels / fails)
   │  302 → {API}/v3/checkout/return/{ref}
   ▼
CheckoutReturnRedirectController  (Y.3-A, API, unauthenticated)
   │  302 → {WEB_APP_URL}/checkout/return?ref={ref}
   ▼
/checkout/return  (Y.3-C, web, auth-gated)
   │  pollUntilTerminal(ref)  via CheckoutStatusService (Y.3-B)
   │     polls GET /v3/checkout/status/{ref} every 2s, ≤60s
   ├── paid ───────────► clear checkout state → /checkout/success/:id
   ├── terminal+unpaid ► failure state (Try again / Back to bag)
   └── timeout ────────► "still processing" → View my orders
```

Source of payment truth remains Noon's **webhook → backend → local Order state**. The return flow never trusts the browser redirect for payment status; it polls the authoritative local status endpoint (which itself never calls Noon — Noon bans aggressive polling).

## 3. Decisions taken (operator-confirmed)

- **Q3.1 = A** — Add a server-side redirect controller on the API
  (`GET /v3/checkout/return/{ref}` → 302 to the web app). Chosen over
  rewriting the Noon return URL to a web host (would break the mobile
  webview, which detects the API path) or relying on invisible infra
  rewrites (not in version control).
- **Q3.2 = yes** — Reconcile the status-label vocabulary to the real
  API statuses (Y.3-D). Fixed `preparing`/`partially_refunded` drift;
  added `fulfilling`/`failed`.
- **Q3.3 = yes** — Poll cadence 2s interval / 60s ceiling (~30 polls).
  Cheap because the status endpoint reads only local DB state.
- **Q3.4 = yes** — Inline failure state on `/checkout/return` with
  Try again (→ /checkout/review, state intact) and Back to bag
  (→ /cart).

## 4. New surfaces & contracts

### API
- `CheckoutReturnRedirectController` — `GET /v3/checkout/return/{order_reference}`
  - Unauthenticated (mounted outside AuthMiddleware, beside the Noon webhook)
  - 302 → `{WEB_APP_URL}/checkout/return?ref={ref}` with `Cache-Control: no-store`
  - Reflects the reference without DB lookup (no existence leak); the
    authenticated status poll enforces ownership (404 cross-user/unknown)
  - Rejects empty / >32-char references with 404
  - New env var `WEB_APP_URL` (defaults to `https://3bayti.ae`)

### Web
- `CheckoutStatusService` (root singleton)
  - `getStatus(ref)` → `CheckoutStatusResponse`
  - `pollUntilTerminal(ref, opts)` → `{ status, timedOut }`; injectable
    `sleep`/`now` seams for deterministic tests
  - `POLL_INTERVAL_MS = 2000`, `POLL_CEILING_MS = 60000`
- `CheckoutReturnPageComponent` — `/checkout/return` (auth-gated,
  RenderMode.Server). Three phases: confirming / failed / processing.
- `CheckoutStatusResponse` type mirrors `GetCheckoutStatusController`:
  `{ order_reference, order_id, status, terminal, paid, total, currency, paid_at }`

### Status vocabulary (single source of truth)
`apps/api Order::STATUS_*` →
`pending_payment, paid, fulfilling, shipped, delivered, cancelled, refunded, failed`.
Frontend `ORDER_STATUS_LABELS` + pill helpers + i18n now match exactly.
Pill colours: positive = paid|delivered; neutral = fulfilling|shipped;
warning = pending_payment; negative = cancelled|refunded|failed.

## 5. Patterns reinforced

- **Polling primitive with injectable timing seams** (`sleep`/`now`)
  so unit tests run the loop with a fake clock and zero real delay;
  `drain()` = 8 microtasks per poll iteration to flush
  firstValueFrom → check → sleep → next dispatch.
- **Unauthenticated Noon-facing API routes** live together outside
  the AuthMiddleware group, each with a "NEVER add AuthMiddleware"
  comment and a retrieve/verify-before-trust safety note.
- **No existence leaks**: the redirect reflects input without lookup;
  the authenticated poll is the ownership gate.
- **RenderMode.Server for auth-gated dynamic pages** — added
  `/checkout/return` (query-param based, but still user-specific).

Playwright e2e of the full pay→return→success path needs a live BFF +
Noon sandbox; the sandbox can't run browser binaries. Add to the
existing staging-smoke list (see `m3.2-y.2-closure.md` §6):

13. **Pay success**: complete a Noon sandbox payment → land on
    `/checkout/return` → spinner → auto-route to
    `/checkout/success/:id`; checkout state cleared, cart empty.
14. **Pay declined**: use a Noon decline test card → `/checkout/return`
    → failure state → "Try again" returns to `/checkout/review` with
    addresses + promo intact.
15. **Return refresh / direct hit**: open `/checkout/return?ref=BOGUS`
    → poll 404s → generic failure state (no crash).
16. **Webhook lag**: simulate a slow webhook (>60s) → `/checkout/return`
    shows "still processing" → "View my orders" works; order later
    flips to paid when the webhook lands.
