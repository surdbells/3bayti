All routes are auth-gated via `authActivateGuard`, lazy-loaded, SSR-aware (parametric routes use `RenderMode.Server`).

### Service surface

- **`CartService`** — signal-based, guest cart in localStorage (`bayti_guest_cart_v1`), merges on sign-in, dedupes on `(product_id, size, color, is_custom)`
- **`CartDrawerService`** — drawer open/close + highlight last-added item
- **`AddressService`** — CRUD `/v3/me/addresses` with `defaultShipping`/`defaultBilling`/`hasAny` computeds
- **`CheckoutService`** — checkout-in-progress state in sessionStorage (`bayti_checkout_state_v1`); `initiate()` calls `POST /v3/checkout/initiate`
- **`OrderService`** — list (accumulating + hasMore), detail, cancel, `submitReturn` (multipart FormData)

### API endpoints exercised

| Endpoint | Method | Used by |
|---|---|---|
| `/v3/cart` | GET/POST | Cart |
| `/v3/me/addresses` | GET/POST/PUT/DELETE | Address book |
| `/v3/checkout/quote` | POST | `/cart`, `/checkout/review` (promo) |
| `/v3/checkout/initiate` | POST | `/checkout/review` (Place Order) |
| `/v3/orders` | GET | `/account/orders` |
| `/v3/orders/:id` | GET | success, detail, return form |
| `/v3/orders/:id/cancel` | POST | detail page |
| `/v3/orders/:id/returns` | POST | return form |

All Bearer-bound (direct to `https://api-v3.3bayti.ae`), routed via the existing single-flight refresh interceptor.

## 4. Architectural patterns established or reinforced

### Test infrastructure
- **`drainMicrotasks` helper** (6-8× `Promise.resolve()`) for effect + await chains
- **`flushPending` afterEach pattern** for `provideI18n` to prevent unhandled-promise warnings:
  ```ts
  try {
    const c = TestBed.inject(HttpTestingController);
    c.match(() => true).forEach(req => { if (!req.cancelled) req.flush({}); });
  } catch { /* ignore */ }
  ```
- **`makeFileList` + `setFiles` shim** for `<input type=file>` tests (jsdom lacks `DataTransfer`)
- **Protected method extraction** (e.g. `redirectTo`) over `window.location.*` mutation — testable via prototype spy
- **Static `HttpErrorResponse` import** in spec files (dynamic import doesn't complete in time when used in throw path)

### Forms
- **`mapApiErrors(err, form, mapping)`** is the canonical error-handling shape
  - `mapping` is `Record<errorCode, { field: string | null, key: string }>`
  - VALIDATION_FAILED handled internally (writes per-field errors)
  - Returns `{ unmapped: string[], isNetworkError: boolean }` so caller decides toast strategy
- **Reactive Forms** typed `FormControl` throughout; dynamic validators toggled via `valueChanges` subscription
- **`data-*` attributes** for testability where translate pipe with params returns empty in tests

### Routing
- **Parametric auth-gated routes need explicit `RenderMode.Server`** in `app.routes.server.ts` **BEFORE** the `**` default
  - Otherwise build fails with `getPrerenderParams missing`
  - Applied to: `/checkout/success/:id`, `/account/orders/:id`, `/account/orders/:id/return`

### Component stylesheets
- Angular component styles are scoped — cross-component sharing requires either a global file or duplication
- **Decision: duplicate intentionally** (e.g. `order-detail.scss` duplicates checkout-summary patterns) rather than bloat `checkout.scss` past its budget
- **CSS budget reframed:** `anyComponentStyle.maximumError` bumped 10kB → 16kB to accommodate shared `checkout.scss` (10.96kB serving 5 pages); warning held at 6kB so unbounded growth still surfaces

### SSR
- Parametric routes for user-specific data → `RenderMode.Server` (not Prerender)
- `isPlatformBrowser(this.platformId)` guards before `history.state`, `window.location`, `localStorage`, `sessionStorage`, `window.confirm`

## 5. UX glue wired in Y.2-K

The cross-sub-phase wiring that didn't fit cleanly into any one sub-phase:

- **Cart → Checkout button** (`/cart` → `/checkout/address`): Already wired in Y.2-B with auth-bounce
- **Header user menu → Orders** (`/account/orders`): Already wired in Y.1 (pre-Y.2-H)
- **Order detail → Return CTA** (`/account/orders/:id` → `/account/orders/:id/return`): **Wired in Y.2-K**

Return CTA visibility rules:
- Hidden for: `pending_payment`, `cancelled`, `refunded`, `partially_refunded`
- Shown for: `paid`, `preparing`, `shipped`, `delivered`
- Server has final say on the 14-day window + per-item delivered status; UI surfaces RETURN_* error mappings if the server rejects

## 6. Deferred to staging (Playwright e2e, Chromatic, axe)

Three quality bars were planned for Y.2-K but require infrastructure the sandbox lacks:

### 6.1 Playwright e2e batch
Sandbox can't run Playwright browser binaries (~5 minutes to install + needs a live BFF + API to exercise). Defer to **staging-smoke** instead.

**Staging smoke test list:**
1. **Cart drawer**: Add to bag from PDP → drawer slides in → see line item → click "View bag" → land on `/cart`
2. **Cart page**: Adjust qty + remove + apply promo `WELCOME10` → totals update inline
3. **Guest checkout bounce**: Click "Checkout" while logged out → land on `/login?returnUrl=/checkout/address`
4. **Sign-in merge**: Add to cart as guest → sign in → guest cart merges with server cart, dedupes
5. **Address book**: Create address → mark default shipping → land back at list with default badge
6. **Checkout 3-step**: `/checkout/address` (default pre-selected) → `/checkout/review` (item list + totals + promo apply) → click "Place order" → land on `/checkout/payment` with redirect to Noon
7. **Noon handoff refresh**: Refresh `/checkout/payment` (no history.state) → bounce to `/checkout/review` after 300ms
8. **Order success**: Land on `/checkout/success/:id` (manually with a real order id) → see hero + items + totals + addresses; CheckoutService cleared, cart refreshed
9. **Order history**: `/account/orders` → see 10 orders → click "Load more" → see 20 → click card → land on detail
10. **Order detail cancel**: For a `pending_payment` order, click "Cancel order" → native confirm → status pill flips to "Cancelled"
11. **Return submission**: For a `delivered` order, click "Request a return" → select items → reason "Defective" → upload 1 photo → submit → toast success + back to detail
12. **RTL**: Switch to Arabic; verify drawer slides from `inset-inline-end` (left), totals stay LTR-numeric, headings flip

### 6.2 Chromatic baselines
Run after staging is up; reference cart drawer, all 3 checkout steps, success hero, orders list (empty + populated), order detail (pending vs delivered), return form (empty vs filled).

### 6.3 axe accessibility
Inline `axe.run()` on each new page in staging. Focus areas:
- Cart drawer focus trap on open + Escape to close
- Promo form error announcement (`role=alert`)
- Return form file input keyboard accessibility
- Order card status pill colour contrast (esp. the warning amber pill)
