## Scope summary

Build the customer cart + checkout + order history surface on top of the Y.1 auth foundation. The user can:

1. Add items to the cart (from product detail / category pages) — works for guests AND authenticated users
2. View the cart at `/cart` with line items, quantity adjusters, totals, promo code
3. Sign in if guest → cart is merged into the authenticated cart (POST /v3/cart/merge)
4. Manage shipping + billing addresses via `/checkout/address` (uses `/v3/me/addresses`)
5. Review order summary at `/checkout/review`
6. Initiate Noon hosted-page payment via `/checkout/payment` (the Noon flow itself is Y.3)
7. View order history at `/account/orders` and per-order detail at `/account/orders/:id`
8. Cancel pending-payment orders
9. Submit + manage returns (placeholder for fuller Y.2 sub-phase)

## API contract (Y.2 uses these endpoints — all under `/v3`)

### Cart (auth required)
- `GET    /v3/cart` — returns full cart with items, line totals, currency
- `POST   /v3/cart/items` — `{ product_id, variant_id, quantity }` → updated cart
- `PATCH  /v3/cart/items/:id` — `{ quantity }` → updated cart
- `DELETE /v3/cart/items/:id` — → 204 or updated cart
- `POST   /v3/cart/merge` — body is the guest cart payload → merged cart
- `POST   /v3/cart/quote` — `{ promo_code?: string }` → quote with line breakdown, shipping, tax, total

### Orders (auth required)
- `GET    /v3/orders?status&page` — paginated list
- `GET    /v3/orders/:id` — full detail
- `POST   /v3/orders/:id/cancel` — body `{ reason?: string }` → 200; only valid in pending_payment

### Checkout (auth required)
- `POST /v3/checkout/initiate` — `{ cart_id, shipping_address_id, billing_address_id, promo_code? }` → `{ redirect_url, order_reference }`
- `GET  /v3/checkout/status/:order_reference` — polled by /checkout/return; returns `{ status: 'success' | 'pending' | 'failed', order_id?: number }`

### Addresses (auth required)
- `GET    /v3/me/addresses` — list
- `POST   /v3/me/addresses` — create
- `GET    /v3/me/addresses/:id` — detail
- `PUT    /v3/me/addresses/:id` — update
- `DELETE /v3/me/addresses/:id` — delete
- `PATCH  /v3/me/addresses/:id/default` — set as default

## Architecture decisions

### CartService design

- Root-injected singleton
- Public surface (signals):
  - `cart()` — `Cart | null`
  - `itemCount()` — `number` derived from cart.items.length
  - `subtotal()` — derived
  - `isLoading()` — boolean
- Methods (all async):
  - `addItem(productId, variantId, quantity)` — POST /v3/cart/items
  - `updateQty(itemId, quantity)` — PATCH
  - `removeItem(itemId)` — DELETE
  - `applyPromo(code)` — POST /v3/cart/quote
  - `merge()` — POST /v3/cart/merge with the localStorage device cart
  - `refresh()` — GET /v3/cart
- Behavior:
  - On `AuthService.isAuthenticated()` going true → call `merge()` once, then `refresh()`
  - Guest path: device cart lives in localStorage; reads + writes go through CartService methods that decide local vs API based on auth state
  - On 401 from any endpoint → falls through to refreshInterceptor's normal flow

### Pages (lazy-loaded)

- `/cart` — public; shows guest or auth cart
- `/checkout/address` — `authActivateGuard` (redirect to /login?returnUrl=/checkout/address)
- `/checkout/review` — same
- `/checkout/payment` — same; redirects out to Noon, not really a viewable page
- `/checkout/success` — authActivateGuard
- `/account/orders` — authActivateGuard
- `/account/orders/:id` — authActivateGuard

### Cart drawer (Y.2-A)

- Slide-out from `inset-inline-end` (RTL-aware)
- Trigger: AddItem call returns → CartDrawerService.open() with focus item highlighted
- Content: 3-5 most recent items, mini-totals, "View cart" + "Checkout" CTAs
- Dismiss: outside-click, Escape, close button
- a11y: role="dialog", aria-modal="true", focus trap

### State coordination

- CartService observes AuthService.isAuthenticated (via effect)
  - On false → load from localStorage
  - On true → merge then refresh (one-time per auth transition)
- CheckoutService (introduced in Y.2-D) holds the in-progress checkout choice (selected shipping address id, billing address id, promo code) across the three /checkout/* routes. Same shape as before/after route navigation. Survives Refresh via sessionStorage like /verify-phone in Y.1-G.
