### 1.3 What the migration does mechanically

For every call site:

```typescript
// before
this.networkService.post_request(body, GlobalComponent.<endpoint>)
  .subscribe({ next: (response) => { ... } });

// after
this.networkAdapter.post_request(body, GlobalComponent.<endpoint>)
  .subscribe({ next: (response: any) => { ... } });
```

Plus per-file:
- Import `MobileNetworkAdapter`
- Add `private networkAdapter: MobileNetworkAdapter` to constructor

The adapter:
- Consults the feature flag for the URL/method combination
- If `target='new'`, routes to v3 with translated body + Bearer header
- If `target='old'` OR no entry exists, falls through to `NetworkService` (legacy)
- Always returns the legacy envelope shape regardless of path

This means migration is SAFE even for endpoints without feature flags —
the adapter degrades gracefully to legacy behavior.

## 3. Per-sub-phase verification protocol

For each sub-phase (locked per Q-Verify=A):

1. **Per-file change:** import + DI injection + drop-in call site swap
2. **Per-sub-phase verification:**
   - `pnpm --filter @3bayti/mobile type-check` returns exactly 6 errors (preserve baseline)
   - Mobile Playwright e2e still passes (12 tests across 4 specs)
   - No new `error TS` lines in `src/` (count exact)
3. **Per-sub-phase commit** with:
   - Comprehensive message documenting which call sites changed
   - Status snapshot vs preceding sub-phase
4. **Per-sub-phase push** to remote
5. **Operator informal smoke** between sub-phases on test device (per Q-Verify=A; not blocking)

If any sub-phase fails verification, halt and surface for direction
rather than proceeding.

## 5. Risks specific to M3.2.X.1.5 (Q-Scope=C broader scope)

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Payment migration introduces a regression | Low | **CRITICAL** | Payment endpoints have no v3 equivalents; adapter falls through to legacy (identical behavior to today). Sub-phase E explicitly verifies the fall-through path; operator manually verifies a test payment on staging before commit. |
| Chat service migration breaks chat flow | Low | Medium | No v3 chat endpoints exist; adapter falls through to legacy. Pure structural change; chat behavior unchanged. |
| `read_vendor` path-param substitution edge case | Medium | Medium | Sub-phase C verifies explicitly; adapter already handles `:id` substitution for `/orders/:id/cancel` and `/auth/confirm` patterns. |
| One sub-phase blows the 6-error mobile tsc baseline | Medium | High | Per-sub-phase tsc verification catches at commit time; halt-and-surface protocol per §3. |
| Migration of a file with hidden dependencies (e.g., DI cycle, shared state) | Low | Medium | Pre-commit type-check catches structural issues. If runtime issue surfaces (only visible in Playwright/manual), revert that specific file and split into a separate sub-phase. |
| Operator informal smoke test misses a regression that production users would hit | Medium | Medium | Per-sub-phase commits make bisecting easy. M3.2.X.1-C-FLIP-style revertability for any single file. |
| Estimated effort balloons beyond 6-8 days | Medium | Low | Mechanical work; each call site is the same drop-in pattern. If a sub-phase hits an unexpected blocker, halt + surface rather than push through. |
