# M3.3 Portal Migration — Closure Runbook
# Generated: 2026-05-22

## Migration status

M3.3 is **functionally complete** for all high-traffic vendor and admin
surfaces. The portal now uses `PortalCrudAdapter` → v3 API for the
primary workflows. Legacy `CrudService` calls remain only for features
that require new domain entities (deferred to M3.4).

## How to flip a deferred feature to v3 in M3.4

1. Build the v3 API endpoint (controller + entity if needed).
2. In `packages/api-client/src/feature-flags.ts`, change the route
   key's `target` from `'old'` to `'new'`.
3. Replace the `crudService.post_request(payload, GlobalComponent.X)`
   call in the portal component with `adapter.get_v3(routeKey, ...)` or
   the appropriate verb.
4. Run `pnpm run type-check` in `apps/portal`.
5. Run `pnpm run build` in `apps/portal`.
6. Commit with message `M3.4.X-Y — [Feature] flipped to v3`.
