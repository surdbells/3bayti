OTA updates

Ship a new mobile web bundle over-the-air. Devices get the highest-version active bundle whose native range (Min native to Max native) contains their app version, only if it is newer than what they run. To move devices back, use Roll back to this (it republishes that bundle as the next version); deactivating only stops devices that haven't downloaded a bundle yet.

Publish a bundle

Native range: the bundle is offered only to app builds whose app version (iOS CFBundleShortVersionString / Android versionName) is between Min and Max native. Min native is the app version the bundle was built for; leave Max empty to target exactly that version, so a TestFlight or test build with a higher app version (e.g. 1.8.1) keeps its own web code. A higher build number alone does not separate builds. Use the app version live in the stores (Play Console / App Store Connect), not the one in the repo. Version must be above Max native, or fresh installs of the top app version never take it. Both uses one range for iOS and Android: when their store app versions differ, upload each platform separately.

Build the web bundle, zip it (npx @capgo/cli@8.68.1 bundle zip com.threebayti.app --path www --json), encrypt it (bundle encrypt <zip> <checksum>), then upload the *_encrypted.zip here with its Session key and Checksum. Unsigned plain .zips are accepted only for android on a non-production channel.
